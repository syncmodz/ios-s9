References

Everything this project learned from. Fifteen ports and tools, each with the one thing worth taking from it. If you are starting your own port, this is the shortest path to not repeating our mistakes.

These are links, not copies. Every entry points at its own upstream repository. The full list is in refs/REFS.md, and refs/clone-refs.sh fetches them all.

Start here

ios-sweet

the origin

The base everything else forks from: XNU on a Qualcomm phone, unmodified iOS userland. Read the build system and the sweet_* driver convention first.

Read it

ios-flame

the one bug

Pixel 4 with Metal working. METAL-NEXT.md §4 item 1 documents the ppnum_t truncation — on our phone it silently affected 2018 MB of RAM.

Read it

Portsmith

the map

A catalogue of 115 ports and frameworks with pinned revisions. Find a port to a device close to yours instead of searching GitHub.

Read it

Getting graphics to work

The hardest part of any port, in the order we would attempt it.

ios-sailfish — the ordered Adreno bring-up

iOS 16 on a Pixel 1 with GPU acceleration: CoreAnimation's GLES renderer on Mesa freedreno, through its own kernel driver. 187 patches, and 0119–0127 is the sequence to copy:

PatchWhat it establishes
0119power probe — is the GPU even on?
0121SMMU in identity mode, which unblocks DMA before you understand the SMMU
0124MMIO without write-combining, when the bus will not tolerate it
01262D blit — enough to prove the pipeline works
0127RBCCU / SP power domain, where bring-up usually stalls

devilAPI/ios-sailfish

ios-topaz — proving the display actually works

Redmi Note 12, 204 patches. Its NOTES.md records the exact console lines that prove backboardd drew through the kernel display path — the IOSurface selectors, the IOMFB SwapBegin/SwapEnd traps, and the alternating SWEET FB: swap N layer 0 surface 2|3 that demonstrates double buffering.

If you need to tell "the display works" from "the display looks like it works", this is the reference. The 0901–0911 series covers GPU memory when the GPU powers on but faults.

MakrSas/ios-topaz

ios-apollo — the zap shader

Galaxy S20. The GPU power and TrustZone path: CX/GMU power, EPSS/CPUFreq/SMMU interaction, hypervisor-safe register access, HFI GX power, SQE/CP start, and zap shader loading through TrustZone — the step that stops most Adreno bring-ups. Clearest treatment in the set.

enesuzun2002/hakios-apollo

Chlorophyll

Metal

Translates Apple's AIR (the GPU IR inside .metallib) to Mesa's NIR and implements the Metal API over Gallium. The only complete answer here to "Metal without Apple's driver".

Read it

metal2vulkan

the alternative

Runs Metal shaders and programs on Vulkan. Instead of writing a Metal driver, translate Metal and reuse the phone's Vulkan driver.

Read it

Tooling you will want

Veerhooda's iOS 12 / OnePlus 2 — the HFS+ editor

iOS 12.5.7 on a OnePlus 2, booting from Qualcomm's bootloader into a shim with a real HFS+ root on eMMC.

tools/op2hfs.py is an in-place HFS+ editor — our s9hfs.py is derived from it. If you need to read or write an iOS root filesystem from a host without mounting it, start here. tools/stage-hfs.sh shows how to stage a root image reproducibly.

Veerhooda/iOS · Veerhooda/xnu

HakiOS — iterate without flashing

XNU with its own bootloader and drivers on a Qualcomm phone, booting stock iOS 16.5 userspace — and the same thing in QEMU. The loader goes in through fastboot boot and the system lives in RAM, so a reboot brings the phone back to Android.

That is a far faster loop than flashing, and the QEMU target means you can debug the kernel with no phone attached.

oosexgang/hackios-xnu-kernel

Bergamota — the same SoC as ours

read only, no license

iOS 18.7.8 on a Poco F1 — Snapdragon 845, the same SoC family as this phone — to SpringBoard, with its own kernel. The UFS, display controller and power domain specifics are the same silicon we drive.

This one ships no license, which means all rights reserved. Read it, learn from it, do not vendor it into your own repository.

ry-diffusion/Bergamota

iOSPlus10 — arm64e and PAC

iOS on a OnePlus 10 Pro through UEFI, aiming at iOS 26 with Metal. Its cores have ARMv8.3 PAC, so the arm64e userland runs without the shared-cache rewrite that phones without PAC need.

If you are targeting iOS 15 or later, read this before assuming you must rewrite the dyld shared cache.

MellysInformejtik/slop

klte-ios7 — it is not tied to arm64

iOS 7.1.2 on a Galaxy S5 (Snapdragon 801) — an ARMv7 port of XNU 2107. Proof that the technique works on 32-bit ARM and on much older iOS.

Quantitative101/iOS7-KLTE-GalaxyS5

Why these are links and not code

The working set is 3.5 GB, most of it third-party code already published upstream. Four of these projects ship no license at all — Bergamota, ios-topaz, ios-sailfish and hakios-sm8150 — which under copyright means all rights reserved, so they cannot be redistributed. The rest are MIT, GPL or APSL and could be, but copying them would only make this repository a stale mirror of someone else's work.

The four with no license are all rights reserved by default. They are linked here, not copied, and that is deliberate — do not vendor them into your own repository without asking their authors.

Fetch them

From a clone of the repository:

cd refs
./clone-refs.sh              # everything, ~3.5 GB
./clone-refs.sh --small      # only the ones under 10 MB, ~60 MB
./clone-refs.sh ios-flame    # one or more by name
./clone-refs.sh --list       # show the names

Clones land in refs/src/, which is gitignored.
